## Architecture Decisions

### AD-1: Content Extraction Approach
**Problem**: How to extract content from deployed book URLs
**Decision**: Use requests + beautifulsoup4 for content extraction
**Rationale**: Robust HTML parsing with good handling of various content types in Docusaurus sites
**Alternatives Considered**: Selenium (more complex), scrapy (overkill), regex (fragile)

### AD-2: Embedding Model Selection
**Problem**: Which Cohere model to use for embeddings
**Decision**: Use Cohere's embed-english-v3.0 or equivalent production model
**Rationale**: Production-ready, optimized for English text, good performance/quality balance
**Alternatives Considered**: Other Cohere models, OpenAI embeddings, self-hosted models

### AD-3: Vector Storage Strategy
**Problem**: How to structure data in Qdrant vector database
**Decision**: Store content chunks with metadata (URL, section, etc.) as payload
**Rationale**: Enables rich retrieval with context while maintaining similarity search
**Alternatives Considered**: Simple text-only storage, different metadata schemes

## Risk Analysis

### High Risk Items
1. **API Rate Limits**: Cohere API rate limits may slow processing
   - Mitigation: Implement retry logic with exponential backoff

2. **Qdrant Free Tier Limits**: Storage and query limits may constrain functionality
   - Mitigation: Implement batch processing and monitoring

3. **Content Extraction Issues**: Dynamic content may not be extractable via simple requests
   - Mitigation: Add fallback mechanisms and content validation

### Medium Risk Items
1. **Network Reliability**: Intermittent network issues during content fetching
   - Mitigation: Add retry mechanisms and timeout handling

2. **Content Format Variations**: Different page formats may require different extraction logic
   - Mitigation: Robust parsing with fallbacks
